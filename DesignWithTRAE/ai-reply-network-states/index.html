OEM AI回复 · 网络异常返回状态与重试交互设计

针对 AI回复（AiCommunicate）生成链路的「非正常返回」做状态分级：网络异常 / 生成超时 / 大模型服务失败 / 命中大模型质检 / 返回内容异常 / 配置缺失 / 截图读取失败
统一替换当前「这次生成没有成功 + 原始报错文案」的单一错误页，避免向客户暴露内部信息，并把重试交互做扎实。

复查发现的问题（均已定位到代码）：
  • 信息暴露：HOST_ONLY 分发模式下，宿主回调失败的英文内部文案直接透传给用户（如 “OEM SDK is not initialized…” “The host has not registered…”），还包含内部类名。
  • 不分类：网络断开、模型 429/5xx、超时、内容被质检拦截、解析失败，全部显示同一句“这次生成没有成功”，用户无法判断该怎么办。
  • 重试死路：错误页“重新生成”按钮走的是基于上一轮上下文的刷新流程；首次生成就失败时上下文为空，点击只会弹 Toast“上一轮聊天上下文已失效”，什么也不会发生。
  • 质检无感知：链路中没有任何内容审核识别，命中大模型质检（如 data_inspection_failed / content_filter）会被当成普通失败，用户反复重试反复失败。
  • 刷新失败只弹 Toast：换语气/重新生成失败时仅 Toast + 静默回退旧列表，提示转瞬即逝，用户容易误以为切换成功。
  • 断网等超时：无网络预检查，断网时要等满超时（约15s）才报“超时”，体验差且归因错误。

02错误分类模型：非正常返回 → 状态码

在 UserVisibleFailure 上增加错误类别（category），由 ModelClient / ReplyService / Activity 三层共同归类；原始英文报错与堆栈只写入 AiReplyTaskLogger 日志上报，绝不上屏。

归类流程：ModelClient 返回结构化错误（类别 + 脱敏文案）→ AiCommunicateReplyService 映射为带 category 的 UserVisibleFailure（宿主回调英文消息在此层全部转中文文案）→ MaterialHubActivity 捕获后调用 showError(category, 文案) → 面板渲染对应分类错误卡。

错误卡设计规范：
  • 状态标签：卡片顶部小标签直接说明「非正常返回」类别（网络异常/服务繁忙/质检未通过/暂不可用/读取失败），替代笼统的“这次生成没有成功”。
  • 文案脱敏：说明文案只讲用户能理解的原因与下一步动作；HTTP 状态码、模型名、宿主英文报错、堆栈一律只进任务日志（AiReplyTaskLogger），不上屏。
  • 按钮语义按状态区分：NETWORK/TIMEOUT/MODEL_BUSY/RESULT_INVALID → 「重试」；CONTENT_BLOCKED → 不提供重试（改为返回）；CONFIG_MISSING → 「刷新配置」；CAPTURE_FAILED → 「重新读取」。
  • 重试保护：同一会话连续重试上限 3 次，超限后按钮置灰并显示 10s 冷却倒计时，防止刷接口。
  • 重试防抖：点击重试后立即进入 GENERATING 时间轴页，按钮不可重复点击。

04结果页内嵌「刷新失败」状态（换语气 / 重新生成）

交互规则：
  • 保留旧结果：刷新失败不整页跳错误页，旧候选列表继续可用（与现状一致），但把“转瞬即逝的 Toast”升级为常驻横幅，并带上失败类别（如“网络异常”）。
  • 内联重试：横幅右侧提供「重试」，成功后横幅消失并替换为新列表；连续失败 3 次后横幅提示“刷新多次未成功，建议返回重新读取”。
  • 语气选中态回退：刷新失败后，语气行高亮回到实际生效的旧语气（现状已回退，保持）。
  • 修复重试死路：ERROR 页点「重试」时，若没有可复用上下文（首次生成即失败），自动改走完整入口流程（重新截图/读取），而不是弹“上下文已失效”。
  • 请求前预检：每次发起生成前先检查网络连接，断网直接进 NETWORK 错误卡，不再空等 15s 超时。

05实施落点（下一轮开发参考，本轮不改代码）

1网络层 ModelClient错误返回结构化为「类别 + 脱敏文案」：识别 Network Error / HTTP 429 / 5xx / 内容质检关键词（data_inspection、content_filter、inappropriate、敏感、违规等），不再只返回裸的 “Error: {code} {原始message}”。
2服务层 AiCommunicateReplyServiceUserVisibleFailure 增加 category 字段；宿主回调通道的英文内部消息全部映射为分类 + 中文文案；原始报错只写 taskLogger。
3面板 AiCommunicatePanelControllerPanelState 增加 errorCategory / retryCount / refreshFailedMessage；renderErrorPage 渲染分类错误卡（标签+图标+文案+主操作）；RESULT 页新增刷新失败横幅组件。
4编排层 MaterialHubActivity三条生成流程（极速/识屏、传图、粘贴）+ 刷新流程统一接入分类 showError；请求前网络预检；修复无上下文时重试死路；重试限次与冷却；上报日志带上 errorCategory。

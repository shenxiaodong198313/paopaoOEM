# 10. 企业总席位与 SDK 运行控制方案

> 更新时间：2026-08-17
> 本文是当前唯一生效口径。
> 旧版“企业 -> 批次 -> 实例”模型、整键盘封禁方案、旧受限文案，均已废弃。

## 1. 当前目标

OEM 非私有化版本当前采用“企业开通 + 席位实例统计 + 人工管控 + 弱网容错”的最小闭环方案。

目标如下：

- 基础输入始终可用，不因授权问题整体禁用键盘
- 仅限制增值能力：`AI回复`、`素材库`、企业质检分发
- 后台以企业为主体管理总席位，不再维护批次
- 支持查看席位明细、手工停用/启用、批量操作
- 支持企业总席位随时增减，但 `seat_limit` 仅作统计与运营记账，不做自动运行时限制
- 弱网、安装后短时未上报、请求抖动默认放行
- 已填写正确企业码的企业，不因到期、席位满额、短时上报失败而被自动限制

## 2. 数据模型

### 2.1 企业

企业主表字段以以下信息为核心：

- `enterprise_id`
- `enterprise_name`
- `enterprise_code`
- `customer_id`
- `app_key`
- `status`
- `seat_limit`
- `expires_at`
- `contact_name`
- `contact_phone`
- `remark`

规则：

- 正式企业：`status = active`
- 历史 `trial` 数据按 `active` 兼容处理，不再触发试用期或到期限制
- 停用企业：`status = disabled`
- `seat_limit` 仅作统计、展示与运营记账，不参与自动封禁
- `expires_at` 仅为历史兼容字段，当前策略不再使用

### 2.2 席位实例

席位实例表以设备实际安装和激活记录为核心。

关键字段：

- `id`
- `enterprise_id`
- `install_id`
- `device_fingerprint`
- `host_application_id`
- `first_activated_at`
- `last_active_at`
- `last_resolve_success_at`
- `seat_state`
- `seat_state_reason`

### 2.3 设备去重

同机卸载重装通过以下规则归并：

- 先按 `customerId + channel + hostApplicationId + installId` 查找
- 未命中时再按 `deviceFingerprint` 回查同宿主历史实例
- 命中后复用原席位，避免同机重复占席

## 3. 后台规则

### 3.1 企业列表

后台路径：

- `用户管理 -> 企业用户`

当前能力：

- 开通企业
- 查看企业详情/席位详情
- 停用企业 / 启用企业
- 编辑企业总席位

### 3.2 企业详情

企业详情页当前展示：

- 企业基础信息
- 总席位
- 已占用席位
- 剩余席位
- 停用席位
- 席位明细
- 批量停用 / 批量启用

### 3.3 总席位编辑

企业总席位允许后台直接增减修改。

规则：

- 企业允许随时增减席位数
- 已停用企业也允许修改席位数，便于恢复前先调整容量
- 修改席位数不会自动让任何已开通企业实例进入受限态

### 3.4 席位统计规则

企业总席位做增减时：

1. 后端仍保留 `seat_limit` 字段用于统计、看板与运营记账
2. 已激活实例继续写入席位记录，便于查看设备规模和活跃情况
3. 不再因为 `seat_limit` 变化自动重排或自动封禁任何实例
4. 若需要限制某设备，必须由管理员显式执行手工停用

## 4. 运行时授权规则

### 4.1 基础输入

无论以下哪种情况，基础输入都保留：

- 企业停用
- 席位手工停用
- 接口抖动
- 弱网或短时失败

### 4.2 增值能力限制范围

以下能力受授权状态控制：

- `AI回复`
- `素材库`
- 企业质检分发

### 4.3 弱网与服务异常

以下场景默认成功，不立即限制：

- 安装后首次上报尚未完成
- 网络超时
- 服务端短时异常
- 输入法保活进程下的瞬时请求失败

这些情况只影响统计时效，不应导致已开通企业的增值能力自动受限。

### 4.5 手工停用判定

后台手工停用席位后：

- 该席位运行时返回 `DISABLED`
- 基础输入保留
- `AI回复`、`素材库` 等增值能力受限

### 4.6 企业停用判定

后台停用企业后：

- 企业下所有实例运行时返回 `DISABLED`
- 基础输入保留
- 增值能力受限

## 5. 入口刷新策略

为适配输入法保活场景，当前采用非对称刷新策略。

### 5.1 正常可用态

当入口当前可用时：

- 本次先正常打开
- 后台异步请求最新授权
- 刷新结果写入待生效状态
- 下一次再次打开时优先生效

### 5.2 当前受限态

当入口当前已受限时：

- 当前次打开先走后台线程即时刷新
- 若服务端已恢复，则当次直接恢复可用
- 不再依赖 `force-stop`

### 5.3 刷新挂点

当前刷新挂点位于：

- `AiInputMethodService` 入口层
- `MaterialHubActivity` 页面层补充刷新

原则：

- 允许态：异步刷新，下次生效
- 受限态：即时刷新，当次恢复

## 6. 受限页文案

### 6.1 当前唯一正确文案

素材库：

- `素材库当前被限制使用，请联系企业管理员`

AI回复：

- `AI回复当前被限制使用，请联系企业管理员`

### 6.2 展示规范

- 只显示一条居中文案
- 不显示标题
- 不显示旧版补充说明
- 保留原抽屉关闭按钮

## 7. 后端实现约束

当前后端核心规则如下：

- 企业总席位字段为 `seat_limit`
- 手工停用状态为 `disabled_manual`
- 不再使用 `blocked_full` / `overdue_verify` 作为运行时限制状态
- 席位数编辑后只更新统计口径，不自动触发运行时封禁
- 席位手工启用/停用后允许做状态清理，但不得对其它实例做自动限制

## 8. 前端实现约束

后台前端当前必须支持：

- 企业列表展示总席位、已占用席位、剩余席位
- 企业列表支持“编辑席位”
- 企业详情页支持席位明细和批量停用/启用
- 编辑席位说明文案要明确告知“仅影响统计，不会自动限制企业实例”

## 9. 已废弃方案

以下方案全部废弃，不得继续作为开发口径：

- 企业 -> 批次 -> 实例三级模型
- 正式企业按批次起止时间管理
- 到期后整键盘不可用
- 受限页显示标题 + 多段旧说明
- 依赖强行停止才能刷新授权状态

## 10. 联调与验收要点

验收时至少覆盖以下场景：

1. 企业停用后，`AI回复` 与 `素材库` 都进入受限页
2. 企业恢复后，受限页当次恢复
3. 席位手工停用后，下次打开受限
4. 席位恢复后，当次打开恢复
5. 总席位减小后，已开通企业实例保持可用，仅统计数据变化
6. 总席位增大后，仅统计数据变化，不影响既有实例授权
7. 弱网下不误伤基础输入与已开通企业的增值能力

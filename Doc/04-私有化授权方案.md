# 私有化授权方案

## 适用场景

- 客户无法连接公网
- 客户要求数据不出内网
- 客户要求完全自主管理授权续期
- 客户要求独立部署 License 服务

## 推荐结论

- 私有化客户不要依赖公网在线授权
- 推荐提供“两种可选模式”
- 模式 A：离线 License 文件
- 模式 B：客户内网 License Server

## 模式 A：离线 License 文件

- 我方签发 `license.dat` 或 `license.json.sig`
- SDK 本地使用内置公钥验签
- License 至少绑定：
- `customerId`
- `packageName`
- `certSha256`
- `expireAt`
- `featureFlags`
- `seatLimit`

## 模式 A 的优点

- 接入成本最低
- 不需要客户额外部署服务
- 适合设备规模不大、变更不频繁的客户

## 模式 A 的缺点

- 续期需要重新发 License 文件
- 席位调整和功能调整不够灵活
- 风控能力弱于在线模式

## 模式 B：私有 License Server

- 我方提供可部署在客户内网的 License 服务
- SDK 在内网请求授权和续期
- 客户可以通过管理后台查看激活、席位和状态

## 模式 B 的优点

- 更适合大客户
- 更适合多应用、多渠道、多环境管理
- 更适合做席位控制、续期和日志审计

## 模式 B 的缺点

- 初始部署成本更高
- 需要客户具备最小运维能力

## 私有化客户的授权建议

- 绑定客户 ID
- 绑定宿主包名
- 绑定宿主签名摘要
- 可选绑定环境标识，例如 `prod`、`uat`
- 可选绑定最大激活设备数或用户数

## 私有化续费建议

- 合同到期前生成下一周期 License
- 支持宽限期
- 支持按季度或按年更新
- 支持通过导入 License 文件或内网服务自动续期

## 私有化风控底线

- 仍然要做本地验签
- 仍然要校验包名和签名摘要
- 仍然要保留到期与降级能力
- 不建议把全部授权逻辑裸露在 Kotlin 层

## 实操建议

- 中小私有化客户：优先离线 License 文件
- 大型私有化客户：优先私有 License Server
- 两种模式都统一使用同一套 License 字段模型，避免双轨维护失控

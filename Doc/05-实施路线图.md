# 实施路线图

## Phase 1

- 提纯 `OEM/android/aikeyboard-sdk-ai`
- 明确公开 API 与内部实现边界
- 建立 `OEM/Doc` 双视图 Wiki
- 清理 OEM 孤儿目录与导入残留

## Phase 2

- 将 SDK 拆成 `core/ai/automation/ui` 可选模块
- 引入私有 Maven 分发链
- 补齐 `consumer-rules.pro`
- 固化版本号和发布流程

## Phase 3

- 建立在线 License Server
- 实现 `customerId/appKey/packageName/certSha256` 授权链
- 实现活跃用户或活跃设备统计
- 支持宽限期、续费和远程降级

## Phase 4

- 将关键授权逻辑下沉到 JNI
- 增加反调试、反 Hook、环境完整性检测
- 加固重要常量、协议和授权校验路径

## Phase 5

- 提供私有化 License 文件方案
- 提供私有化 License Server 方案
- 输出私有化部署手册和运维手册

## 建议优先级

1. 先把 SDK API 收口
2. 再把交付方式 AAR 化
3. 再做授权和计费
4. 最后做深度加固和私有化部署

## 当前下一步建议

- 下一轮优先做 `aikeyboard-sdk-ai` 的对外 API 收口文档
- 明确哪些能力属于第一版对外交付范围
- 同时设计 License 数据结构和验签接口

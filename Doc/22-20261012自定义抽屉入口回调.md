# 2026-10-12 自定义抽屉与剪贴板回复入口接管

## 需求核对与实现基线

客户要求自定义抽屉入口可由宿主完全接管。核对源码确认原版无入口回调；此外状态栏在调用统一入口前已执行 `requestHideSelf(0)`，不能只修改服务中的统一方法。

- 新增 `OemCustomDrawerEntryHandler.onEntryClick(Context, String): Boolean` 与可空 `entryHandler`，默认 `null`。
- 在注册项查找成功后、编辑器和 material addon 校验前处理回调，主线程调用；返回值不消费，异常静默捕获，不回退 SDK 抽屉，不收键盘、不创建 Activity/内容、不产生 SDK 点击日志或 Toast。
- 状态栏去掉提前收键盘，由原默认启动分支处理。工具条和状态栏共用服务入口。
- 新字段追加于 `contentFactory` 后，保留旧位置参数与 `component5` 的含义；保留旧五参数 JVM 构造函数。旧源码重新编译接入，新版 data class 的默认参数/copy 二进制签名变化，已编译依赖应一同重编，不宣称无需重编的完整 ABI 兼容。
- 宿主回调收到 IME Service Context。自行启动 Activity 需按 Android 要求设置 `FLAG_ACTIVITY_NEW_TASK`；不要在回调中递归调用同 id 的 `OemImeSdk.openDrawer`（该方法仍进入相同路由）。
- 保留注册开关、配额、工具面板分页、工具条顺序/显隐/隐藏池及 `custom_<id>` 持久化和注销清理。

## 追加需求 8（仅 OEM）

发布前用户追加剪贴板智能回复接管和 UI 调整，本次合并到尚未上线的同一版本。新增 core 包 `OemClipboardQuickReplyHandler` 与 `OemImeSdk.setClipboardQuickReplyHandler`；仅 clipboardReplyText 非 null 的 AI_REPLY 请求在企业功能/授权校验前回调宿主，主线程、忽略返回值、异常静默。注册回调时按钮不依赖 AI/material 切片；上层点击不清除剪贴板建议（含回调内反注册的场景）。null 恢复原 SDK 流程，普通 AI 回复与粘贴不变。

历史工具条文档的 6 项过时，当前代码 `MAX_TOOLBAR_ITEMS=5`；保持 5 项不变，测试改用源码常量，修正文档。早期测试 fixture 因硬编码 6 项断言失败，不计为 SDK 回调故障或通过证据。

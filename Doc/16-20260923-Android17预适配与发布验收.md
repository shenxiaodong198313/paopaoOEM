# 1.0.0.20260923 Android 17 预适配与发布验收

范围：OEM 输入法运行时、七个公开 SDK、独立企业演示宿主、官网文档与演示包。

## 适配结论

- 保持 `targetSdk 36`。本轮是 Android 17 兼容预适配，不宣称已通过 Android 17 实机或云测，也未启用 targetSdk 37。
- 输入法运行时由 `app:1.7` 升为 `app:1.8`，七个公开 SDK 统一升为 `1.0.0.20260923`。
- OEM 演示宿主默认拒绝明文流量；SDK Manifest 不再替集成宿主放开全局明文流量。旧的 15 处调试 HTTP 上报已移除，正式服务仍走 HTTPS。
- OEM 演示宿主版本号升为 `202609230` / `1.0.0.20260923`，正式包名维持 `com.enpaopaokeyboard.ai`。应用密钥从本机忽略文件或环境变量注入，不写入 Git。
- `targetSdk 37` 对本地网络、动态代码加载、后台启动、大屏布局等行为的影响另行专项验证；本轮不将它们作为已完成项。

## 本地构建与设备验证

- 按 `07-SDK实施与发布清单.md` 的三阶段流程，从零重建并发布 Fcitx 运行时及五个 native 库、OCR 与九个 Stellar 模块、七个公开 SDK，均成功。仓库包含 23 个 AAR，七个公开模块有非空 R8 mapping。
- OEM 内部宿主 `Release` 构建成功。构建期间修正宿主与 core SDK 重复编译模型类和 `OemAddons` 导致的 D8 重复类错误，保留宿主专用 `OemHostRuntime`。
- macOS 导出脚本 `OEM/SDK/export-sdk.py` 检查目录中的 22 个 catalog 制品及各自 AAR/POM/module，生成完整 Maven 仓库交付 ZIP；ZIP 完整性检查通过。
- 仅从导出的 SDK 仓库构建独立演示宿主 `Release/R8` 成功；该构建用于验证企业正式集成时的 R8 兼容性。官网演示 APK 则按用户明确的用途，使用 `Debug` 安装包模拟第三方空白宿主接入 SDK，不要求配置生产发布签名。
- 为避免覆盖线上签名的演示应用，使用独立测试包名和临时测试签名在 PLQ110 / Android 16 设备安装；启用输入法后，在系统设置搜索框输入 `ni`，点击候选词后成功上屏“你”。未见该测试进程的 `FATAL EXCEPTION`。测试后已恢复设备原默认输入法。
- 官网 Debug 构建另以独立测试包名安装到同一设备，完成启动、输入 `ni` 与候选词“你”上屏；测试后恢复原默认输入法并卸载测试包。
- 生成并检查官网 SDK PDF（28 页）；网站 JS 语法和 catalog 版本一致性通过。

构建日志：`/tmp/oem-android17-stage1.log`、`/tmp/oem-android17-stage2.log`、`/tmp/oem-android17-stage3.log`、`/tmp/oem-android17-internal-app-rebuild2.log`、`/tmp/oem-android17-demo-build2.log`、`/tmp/oem-android17-demo-debug.log`、`/tmp/oem-android17-demo-debug-test.log`。日志位于本机临时目录，不作为长期归档。

- 发布日期：2026-09-24；官网 `https://www.paopaoime.com/oem/`。公开版本 `1.0.0.20260923`，运行时 `app:1.8`。
- staging 目录先对 32 项文件做 SHA256 校验，全部通过；包括 23 个 AAR、ZIP、Debug APK、PDF、catalog、官网 JS/HTML 和版本说明。然后将 staging 整目录切换为公开 `/var/www/paopao/website/oem`。

## 发布后从零集成

- 从官网 HTTPS 重新下载交付 ZIP，SHA256 与已发布版本一致。将 ZIP 解压到新建的独立宿主工程，只使用其中的 `local-sdk/repo`，不引用 OEM SDK 源码和构建输出。
- 独立工程 `Debug` 与 `Release/R8` 均成功构建：`/tmp/oem-android17-postpublish-consumer.log`，88 个任务执行。
- 将该线上交付包构建出的 Debug 宿主以独立测试包名安装到 PLQ110 / Android 16。应用启动、输入法启用、输入 `ni` 和候选词“你”上屏均通过，未见该进程 `FATAL EXCEPTION`。测试后恢复原默认输入法并卸载测试宿主，保留设备上原有线上演示包。
- 本轮未在 Android 17 设备或 vivo 云测验证，也未升级 targetSdk 37；正式宣传“Android 17 已全面适配”前须补测。海外 ADI 开发者身份注册属于平台账号事项，不能通过代码构建验证。云端 AI 真实生成及所有自动化功能不在本轮设备验收范围。

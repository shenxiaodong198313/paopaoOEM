## 失败分类与 MD 优化

| 现象 | 原因 | 处理及文档修订 |
|---|---|---|
| No cached version / lint、core-ktx、material-ripple 缺失 | 首次构建误用 offline | 首次联网解析，文档区分 wrapper 下载与依赖缓存；避免全局盲目清缓存 |
| Java 17 toolchain 不可用 | Gradle JVM 与编译 toolchain 选择不同 | 显式 JAVA_HOME 和已安装 JDK 路径，编译目标保持 17 |
| 内部 Paddle AAR 找不到 | 同一次 Gradle 配置先解析了尚未发布的内部依赖 | 发布 SOP 改为 Fcitx → Paddle/Stellar → 公开 SDK 三次独立调用 |
| PowerShell 将 -D 参数识别为 task | 点号参数未正确引用 | JVM/网络参数放入 gradle.properties；原生命令记录 stderr 后检查退出码 |
| 企业宿主 Release/R8 Missing classes | 可选平台/桌面/编解码扩展未覆盖 | 审查来源并提供 `oem-host-optional-r8.pro` 精确规则；保留 R8，禁止屏蔽缺失 OEM 运行类；重新构建成功 |
| adb install 长时间无输出 | ColorOS 在深度扫描界面等待 | 按系统界面完成「更多 → 开始深度扫描」；MD 原有 FAQ 适用，日志和设备前台必须一起检查 |
| 模型配置接口 401 | SDK 授权和云端模型登录态独立 | MD/PDF 明确两者区别；按用户指示不配置云端模型 |

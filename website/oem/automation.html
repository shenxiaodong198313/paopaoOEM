自动化配置

泡泡输入法 OEM 自动化配置说明

本页说明自动化套餐的授权、发布与首次恢复动作，作为对外文档站中的自动化配置频道使用。

开始配置 下载 AI 一键装 SOP 查看集成主文档 查看 API 页面

适用范围

自动化套餐客户 仅在明确交付自动化套餐时启用本页配置，默认集成不需要打开。

关键动作

授权 / 发布 / 恢复 重点覆盖宿主包名确认、权限授予、输入法自动化引擎重新发布与首次恢复链路；当前基线为 Stellar v1.0.18。

页面作用

配置说明 + 验收路径 用于指导客户完成自动化配置，并在交付后按固定步骤完成验收。

Step 1

确认最终宿主包名

  1. 自动化授权按最终安装到设备上的 `applicationId` 生效，不按源码包名生效。
  2. 如果客户使用了 `applicationIdSuffix`，必须以最终包名为准。
  3. 例如 `release` 是 `com.example.host`，`debug` 可能就是 `com.example.host.debug`。

Step 2

授予 WRITE_SECURE_SETTINGS

  1. 自动化快速启动链会尝试打开无线调试并连接本机 ADB，这一步要求宿主具备 `WRITE_SECURE_SETTINGS`。
  2. 如果没有这项权限，常见现象就是“自动化服务启动失败”“服务未运行”“授权应用为空白”。

授权示例

adb shell pm grant com.example.host.debug android.permission.WRITE_SECURE_SETTINGS

Step 3

补 Application 初始化

Application 示例

OemHostRuntime.initialize(this)

Step 4

补 Manifest 元数据

Manifest 示例

<meta-data
    android:name="com.paopaoime.oem.enableAutomation"
    android:value="true" />

<meta-data
    android:name="com.paopaoime.oem.enableAutomationSettingsEntry"
    android:value="false" />

// enableAutomationSettingsEntry 默认 false：仅企业明确需要时才显示“自动化设置”入口
// 自动化权限元数据已由 SDK 默认合并，无需额外暴露底层引擎键名

Step 5

按宿主包名重新发布输入法自动化引擎

  1. 宿主包名变化后，输入法自动化引擎制品必须重新发布。
  2. 否则会出现“授权应用为空”“服务未运行”“Binder 无法握手”等问题。

发布参数示例

automationEngineApplicationId=com.example.host.debug
automationEngineDefaultAllowedPackages=com.example.host.debug,com.example.host

Step 6

重新导出 SDK 压缩包

  1. 输入法自动化引擎重新发布后，必须重新导出 `OEM/SDK`。
  2. 对客户交付的应该是新的 `oem-sdk-delivery-*.zip`，而不是只告知参数。
  3. 固定下载地址：oem-sdk-delivery-latest.zip

Step 7

检查 Release/R8 保护

  1. `stellar-server-1.0.0.aar` 内必须包含 `proguard.txt`。
  2. `proguard.txt` 必须保留 `roro.stellar.server.**`，避免 Release/R8 后 `app_process` 找不到 `ServerBootstrap`。
  3. `proguard.txt` 必须包含 Android hidden API 的 `-dontwarn`，例如 `ActivityThread`、`DdmHandleAppName`、`SELinux`。
  4. 若漏掉该保护，常见现象是开关停留在“正在启动自动化服务”、授权无法落盘、`logcat` 出现 `ClassNotFoundException: roro.stellar.server.bootstrap.ServerBootstrap`。

Step 8

完成验收

  1. 确认宿主能打开内嵌“输入法自动化引擎”。
  2. 确认宿主已具备 `WRITE_SECURE_SETTINGS`。
  3. 确认自动化引擎 Provider Authority 已按当前宿主包名完成配置。
  4. 确认“授权应用”中能看到当前宿主包名。
  5. 确认启动服务后，重新进入输入法设置页仍可正常打开自动化相关入口。
  6. 确认第三方 App 跳转到自动化引擎授权时，权限为“询问”的来源 App 可触发官方快速授权弹窗。
  7. 点击自动化开关后，`adb shell ps -A | findstr stellar` 能看到 `stellar_server`。
  8. `adb logcat` 能看到 `Calling main entry roro.stellar.server.bootstrap.ServerBootstrap`，且不能出现 `ClassNotFoundException`。
  9. 输入法设置页自动化摘要显示已检测到可用自动化引擎服务，并提示当前输入法已获得授权。

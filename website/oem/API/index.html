API接口

泡泡输入法 OEM API 联调说明

本页用于说明 OEM 对外交付保留的核心联网边界，作为对外文档站中的 API 接口频道使用。 企业宿主只需要配置统一的 `apiBaseUrl`，即可按标准协议接入输入质检、素材库服务端管理、AI 代理与自动化能力。

开始素材库联调 下载 AI 一键装 SOP 查看集成主文档 查看自动化配置

演示域名

https://api.enterprise.example.com 这里只展示企业自有域名占位方式，正式接入必须显式替换，不再默认回退到 `paopaoime` 域名。

接口边界

质检 / 素材库 / AI / 自动化 当前页面聚焦对外交付仍保留的联网配置与联调能力，未交付能力不在此页承诺。

页面作用

标准协议 + 在线演示 既可查看标准字段，也可在线上传附件、创建素材、修改删除并查看 JSON 详情。

Host Config

企业 API 域名

宿主统一通过 `com.paopaoime.oem.apiBaseUrl` 指定企业后端基础域名。`customerId` 填我方交付的企业码，`appKey` 当前与企业码同值，`channel` 无特殊约定保持 `release`。若企业未开通、企业被停用，或当前设备席位被管理员停用，AI 回复、素材库等增值能力会显示受限。

Manifest 示例

<meta-data
    android:name="com.paopaoime.oem.apiBaseUrl"
    android:value="https://api.enterprise.example.com" />

AI Mode

双模式 AI

  1. `proxy`：只走企业代理，适合统一鉴权、审计和额度控制。
  2. `direct`：SDK 直接请求兼容 OpenAI 的模型地址，适合快速联调。
  3. `dual`：优先代理，代理未配置或不可用时自动回退到直连。

AI Manifest 示例

<meta-data
    android:name="com.paopaoime.oem.aiMode"
    android:value="dual" />
<meta-data
    android:name="com.paopaoime.oem.aiOpenAiBaseUrl"
    android:value="https://your-openai-compatible-host/v1" />
<meta-data
    android:name="com.paopaoime.oem.aiOpenAiApiKey"
    android:value="your_api_key" />
<meta-data
    android:name="com.paopaoime.oem.aiOpenAiModel"
    android:value="gpt-4o-mini" />

Material Library

素材库标准协议

素材库原有“本地添加素材”能力保持不变。本次新增的是一套标准版服务端对接协议：客户可以在自己的 `apiBaseUrl` 下，按相同字段协议实现素材上传、查询、修改、删除；也可以在网关层自行映射路径。

重点约束：单个文案/图片/文档/视频都属于素材；多类型编组素材通过 `parts` 数组按顺序组合。

客户端同步策略已更新为“无感后台同步”：用户每次唤起输入法时，系统都会在后台静默检查最近 10 条元数据并按需补齐附件。

后台低频任务默认每小时检查一次远端素材状态；输入法保活周期内则继续静默同步，因此抽屉首页不再单独展示下载按钮。

推荐标准路径

POST {apiBaseUrl}/api/v1/material-library/assets:upload
GET  {apiBaseUrl}/api/v1/material-library/assets
GET  {apiBaseUrl}/api/v1/material-library/assets/{assetId}
POST {apiBaseUrl}/api/v1/material-library/materials
GET  {apiBaseUrl}/api/v1/material-library/materials
GET  {apiBaseUrl}/api/v1/material-library/materials/{materialId}
PUT  {apiBaseUrl}/api/v1/material-library/materials/{materialId}
DELETE {apiBaseUrl}/api/v1/material-library/materials/{materialId}

Input QA

真实可写演示接口

演示写入接口：`POST /api/v1/oem/input-qa-demo/sessions`，请求体会实时写入独立 JSON 存储，便于在线核对字段结构。

四种模式怎么测

  1. `CLOUD_ONLY`：只要本页“最近 10 条会话”出现新记录，即可判定云端上传链路正常。
  2. `HOST_ONLY`：本页不会出现真实会话，应改看宿主 App 自己的会话接收列表、日志或落库表。
  3. `DUAL_WRITE`：本页和宿主 App 两边都应出现同一时段的新记录，适合作为首次联调默认模式。
  4. `LOCAL_ONLY`：本页不会出现真实会话，此模式仅用于本地排障或临时关闭外部流转。

真实联调建议

  1. 先把宿主 `apiBaseUrl` 指到企业联调域名，例如 `https://api.enterprise.example.com`；不要留空，也不要再依赖 `paopaoime` 域名默认值。
  2. 真实输入建议直接在微信、企业微信、浏览器等外部第三方 App 中输入一句固定文案。
  3. 若同时验证宿主回调，宿主侧记录里的 `targetPackageName / targetAppName` 应显示真实输入发生的外部第三方 App。
  4. 本页读取的是最近 10 条云端会话；宿主侧若配置了 `HOST_ONLY` 或 `DUAL_WRITE`，还应自行实现 `sessionArchiveListener` 用于展示或落库。

宿主回调和云端协议不是同一个对象

  1. 本页“请求体示例”展示的是云端输入质检写入协议，用于官网/API 页验证上传链路。
  2. 宿主 `sessionArchiveListener` 收到的是 `OemSessionArchiveEvent`，核心字段为 `eventId / sessionId / hostApplicationId / targetPackageName / targetAppName / maskedContent / inputSource / policyState / timestamp`。
  3. `channel` 目前属于宿主初始化与 Manifest 配置维度，用来区分客户渠道/环境，不是当前云端输入质检请求体的必填字段。
  4. 验收时不要把官网最近 10 条和宿主回调对象混为一套口径；前者看云端上传，后者看宿主自管数据。
